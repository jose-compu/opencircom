OpenCircom reference

v0.8.0 — 101 circuit templates, CLI tooling, integration guides, and auto-generated template reference from circuits/**/*.circom.

Overview

OpenCircom is a library of reusable Circom 2.x templates for zero-knowledge applications: hashing (Poseidon, MiMC, SHA-256), comparators, Merkle proofs, identity (Semaphore-style), voting, MACI v1 building blocks, and utilities. There is no dependency on circomlib; implementations are self-contained and covered by 163+ real Groth16 tests.

Install via npm, add the circuits folder to your Circom include path (-l), and compose templates in your own circuits. Use the Hardhat or Foundry boilerplates for a full compile → verifier → test pipeline.

Installation

npm install opencircom

Peer dependency: circom 2.x must be installed and available on PATH. OpenCircom does not bundle the compiler.

Package version: ^0.8.0. Circuits live under node_modules/opencircom/circuits/.

Include paths & compilation

Reference templates with paths relative to the include directory:

include "opencircom/circuits/hashing/poseidon.circom";
include "opencircom/circuits/merkle/merkle_inclusion.circom";

Compile with the opencircom circuits on the include path:

# Manual
circom your.circom --r1cs --wasm -o build -l node_modules/opencircom/circuits

# CLI (adds include path automatically)
npx opencircom compile circuits/YourCircuit.circom -o build

# Print include path only
npx opencircom path

If you clone or submodule the repo as opencircom/ in your project root, use -l opencircom/circuits instead.

Hardhat integration

  1. Add opencircom as an npm dependency.
  2. In your Circom build step, pass -l node_modules/opencircom/circuits.
  3. Use snarkjs (or your flow) to generate the Groth16 verifier Solidity contract.
  4. Deploy or import the verifier in Hardhat tests and call it from your application contracts.

See the opencircom-hardhat-boilerplate starter repo for a wired pipeline (compile circuits, generate verifier, JS tests).

Foundry integration

  1. Install via npm: npm install opencircom, or add as a Git submodule under lib/opencircom.
  2. Run circom with -l node_modules/opencircom/circuits (or -l lib/opencircom/circuits).
  3. Generate the Solidity verifier with snarkjs; place the .sol file in src/.
  4. Run forge build and forge test.

See the opencircom-foundry-boilerplate for submodule setup, npm compile scripts, and Solidity tests.

Testing

Tests compile real circuits, run a small Powers of Tau ceremony, generate Groth16 proofs with snarkjs, and verify — no mocks on the proof path.

git clone https://github.com/jose-compu/opencircom.git
cd opencircom
npm install
npm test

npm test runs compile:test (all test circuits) then setup:zk (ptau + zkey). First run can take about a minute.

Coverage includes hashing, comparators, Merkle (inclusion, sparse, incremental, update, allowlist), identity, nullifiers, voting, MACI, arithmetic, utils, string validation, and full Groth16 prove/verify flows.

Security

  • Range checks: Use StrictNum2Bits(n) or RangeProof(n) for untrusted inputs; LessThan(n) assumes inputs < 2n.
  • Binary selectors / bits: Prefer SafeAND, SafeOR, SafeMux1, SafeMux2, SafeBits2Num(n) for untrusted inputs. Raw AND/OR/Mux1/Mux2/Bits2Num are building blocks without binary constraints.
  • Merkle: pathIndices[i] are constrained binary in-circuit; Switcher constrains sel to {0,1}.
  • Nullifier: Use a unique externalNullifier per action to avoid cross-action replay.
  • Hashing: Poseidon uses standard Hades parameters; constants in circuits/hashing/poseidon_constants.circom.
  • Audit (0.5.0) / Safe wrappers (0.8.0): Binary constraints and range checks hardened in Switcher, ForceEqualIfEnabled, IncrementalMerkleInclusion, DivRem, and PadPKCS7; Safe* templates added for gates, mux, and Bits2Num.
  • MACI: EdDSA, ECDH shared keys, and full DuplexSponge encryption remain off-circuit (coordinator layer). See MACI v1 spec.

Full notes: SECURITY.md on GitHub.
